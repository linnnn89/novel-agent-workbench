# 桌面保存、任务和删除的生命周期

## 目标与范围

保留生成→审稿→精修→确认的现有产品流程。此次重写集中于现代桌面桥接层的工作区操作协调和前端保存/删除生命周期，不替换磁盘格式、模型适配器或 CLI。协调器只覆盖同一个 WorkbenchBridge 实例；跨进程互斥仍由现有存储机制负责，不能将此设计理解为多实例安全性保证。

## 后端职责：操作准入，不等待 I/O

同一桥接实例使用一把短暂的状态锁维护：

- IDLE：没有任务或本地访问
- INSPECTION(n)：一个或多个资料读取/预览；部分服务读取会初始化或迁移数据，因此也需要登记生命周期
- LOCAL(name)：一项本地修改，例如保存、删除、导入、切换项目库
- JOB：一个后台生成/审稿/记忆任务

状态锁仅用于检查、登记和释放；磁盘操作、对话框和目录刷新均在锁外执行。多个 INSPECTION 可以并存；LOCAL/JOB 与其他登记操作互斥。冲突立即返回明确错误，不排队、不偷偷重试，不以保存成功作为删除条件。正常返回和异常都释放登记。

主要本地修改入口共用 _local_operation：正文、章节输入、记忆、资料、确认、重命名、删除、新建、导入、导出、设置、恢复及项目库切换。涉及初始化/迁移的主要概览、预览和生成前设置准备也纳入登记。纯读取入口及全局模型配置管理不是新增的数据事务层；服务内部原有多文件写入一致性不由此 PR 解决。

已开始的保存如果报错，释放登记后可以立即删除。若底层 I/O 一直不返回，删除会立即说明操作尚未结束，而不是挂在全局锁上；不能安全强杀 Python 写入线程，也不能保证故障磁盘可被删除。用户需处理磁盘问题或重启程序后重试。停止任务的状态检查不会被磁盘写入占用的锁拖住。

删除的提交点是服务删除成功。其后的工作区刷新失败返回成功和 warning，不能谎报删除失败并保留已失效的界面状态。底层删除自身的多文件失败/回滚仍遵循现有存储行为。

## 前端职责：编辑生命周期与回调归属

每个保存请求携带项目库、作品、稿件、导航版本和作品保存代次。队列执行前检查代次；回调检查代次及当前编辑身份。旧成功/失败回调不能污染新稿件的保存状态。

删除是一个完整操作，而不是先调用通用保存：

1. 用户输入原有确认短语；提示会放弃目标作品的未保存编辑。
2. 登记 deletingProject，禁止重复删除、导航和关闭；使目标作品旧保存请求失效。
3. 暂停自动保存计时器；删除当前作品时暂时只读。删除其他作品时当前正文仍可编辑，新编辑登记为待保存，删除结束后恢复一次保存计时，不清空当前缓冲。
4. 后端拒绝/失败：保留内容和 dirty 状态，恢复原有编辑权限；只恢复原本存在的计时器一次，不生成无限重试。
5. 后端提交成功：清理已删作品的编辑缓冲，刷新列表；如删除的是当前作品，保留原来的自动选择下一作品行为。
6. 删除后的刷新/选择失败只提示后续刷新问题，不冒充删除失败。

单版本删除也以服务删除成功为提交点：目录刷新失败返回成功和 warning；前端从已有目录移除目标版本、保留其他作品，并切换到剩余版本或清空最后版本。后续打开稿件、读取概览失败单独提示。

记忆保存和审稿完成后的作品概览刷新也属于各自的前端操作生命周期：刷新结束后才解锁记忆操作或稿件导航，避免紧接着的压缩任务、切换稿件保存与后台 inspection 冲突。概览刷新失败仍释放界面状态，不把已经成功的记忆保存或审稿结果改报为失败。

章节建议在同一次 inspection 登记内读取设置、章节、待提交输入和确认稿。操作冲突或读取失败返回错误，不以 chapter_001 和空提示词冒充成功。

## 回归重点

- 生成中拒绝删除；生成完成后正常删除
- 保存暂停不占用状态锁；删除/任务启动即时拒绝，状态接口可响应
- 保存异常释放登记，删除不要求保存成功
- 删除期间拒绝保存及新任务；删除后迟到保存不能新建项目
- 状态登记正常/异常清理，检查操作并发及与修改互斥
- 删除失败保留正文、恢复计时器一次
- 旧保存队列及旧成功/失败回调失效
- 删除其他作品保留当前编辑，删除当前作品仍选择下一作品
- 删除其他作品成功或失败后，恢复原有待保存及删除期间新编辑的自动保存
- 删除已提交但刷新失败仍返回成功
- 单版本删除提交后的刷新失败保留目录与正确的编辑选择
- 章节建议冲突/读取失败明确报错，全部章节读取结束前阻止修改和任务启动

测试使用临时数据、模型桩及 Node VM；不调用真实模型 API。Windows WebView 实机交互、磁盘物理故障、多实例并发不在本次自动测试覆盖中。
